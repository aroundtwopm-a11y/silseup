# DOMAIN.md — 요금제 추천·구독 서비스

> 이 문서는 도메인 전문가 인터뷰 내용을 정리한 것이다.
> - **확인**: 인터뷰에서 전문가가 답하거나 가정을 확인한 내용
> - **추정**: 전문가가 "아마", "~같아"라고 말한 내용. 근거 확인이 필요하다.
> - 금액(위약금, 결합할인)은 이번 범위에서 예시값을 쓴다.

## 1. 배경

- 모바일 웹으로 만드는 요금제 추천·가입 서비스다.
- 고객은 약정이 끝났을 때 통신사를 바꾸거나 요금제를 낮추면 더 싸게 쓸 수 있을 것 같아서 요금제를 바꾸려 한다. (추정)
- 휴대폰을 살 때 보조금 때문에 비싼 요금제에 가입했다가 나중에 낮추려는 경우가 많다. (추정)
- 약정이 끝나면 고객에게 통보가 가고, 고객은 U+one 앱에서 이를 확인한다. (추정)
- 하지만 요금제가 너무 많고 혜택, 결합할인, 약정 기간을 이해하기 어려워서 고객은 결정하지 못한다. (확인)
- 결국 고객센터에 전화하는 경우가 많다. (추정)
- 이 서비스의 목표는 고객이 고객센터에 전화하지 않고도 요금제를 비교하고 가입 신청까지 끝내는 것이다.

## 2. 용어집

| 용어 | 정의 | 비고 |
|---|---|---|
| 가입 | 고객이 요금제를 신청하는 행위. 화면과 문서에서는 이 용어로 통일한다. | 기존 고객의 요금제 변경과 번호이동 고객의 신규 가입을 모두 '가입'이라고 부른다. |
| 구독 | 요금제에 가입하는 것 자체. | 서비스 이름에만 쓴다. 화면과 문서에서는 '가입'을 쓴다. |
| 기존 고객 | 본인인증 후 U+ 가입 정보가 확인되는 고객. | |
| 번호이동 고객 | 본인인증 후 U+ 가입 정보가 없는 고객. 다른 통신사에서 옮겨 온다. | |
| 추천 요금제 | 고객 조건에 맞춰 보여 주는 요금제 3개. | |
| 약정 기간 | 가입할 때 고르는 의무 사용 기간. 12개월 또는 24개월. | 무약정은 선택지에 없다. |
| 결합할인 | 다른 상품과 묶어서 받는 요금 할인. 이번 범위에서는 받을지 여부만 고른다. | 인터넷·TV 같은 결합상품 가입은 하지 않는다. |
| 위약금 | 약정이 남은 고객이 요금제를 바꿀 때 내는 금액. 이번 범위에서는 예시값으로 안내한다. | |
| 유심 유형 | 일반 유심 또는 eSIM. 번호이동 고객만 고른다. | |
| 가입 신청 상태 | 접수, 처리 중, 완료, 취소. | 5장 참고 |

## 3. 역할

| 역할 | 목표 |
|---|---|
| 기존 고객 | 실제 사용량에 맞는 더 저렴한 요금제를 찾아서 바꾼다. 약정이 남아 있으면 위약금을 알고 결정한다. |
| 번호이동 고객 | 월 예산과 지금 내는 요금을 기준으로 U+ 요금제를 비교하고 가입한다. |

- 이번 범위의 사용자는 고객뿐이다. 상담사나 운영자 화면은 만들지 않는다.

## 4. 핵심 흐름

### 4.1 공통 시작
1. 고객이 로그인하거나 본인인증을 한다.
2. U+ 가입 정보가 있으면 기존 고객 흐름으로, 없으면 번호이동 고객 흐름으로 간다.

### 4.2 기존 고객: 요금제 변경 가입
1. 실제 사용량을 바탕으로 추천 요금제 3개를 본다.
2. 요금제 상세에서 혜택, 결합할인, 약정 조건을 확인한다.
3. 가입 옵션으로 약정 기간(12개월 또는 24개월)과 결합할인을 받을지 고른다.
4. 약정이 남아 있으면 예상 위약금을 확인하고 동의한다.
5. 입력 정보를 확인한 뒤 가입 신청을 한다. 이때 가입된 개인 정보와 결제 정보를 그대로 쓴다.
6. 신청이 접수되고 완료 화면이 나온다.

### 4.3 번호이동 고객: 신규 가입
1. 월 예산과 지금 내는 요금을 입력한다.
2. 입력한 조건으로 추천 요금제 3개를 본다.
3. 요금제 상세에서 혜택, 결합할인, 약정 조건을 확인한다.
4. 개인 정보를 입력한다.
5. 가입 옵션으로 약정 기간, 결합할인 여부, 유심 유형(일반 유심 또는 eSIM)을 고른다.
6. 결제 정보를 입력한다.
7. 입력 정보를 확인한 뒤 가입 신청을 한다.
8. 신청이 접수되고 완료 화면이 나온다.

### 4.4 가입 신청 내역 조회와 취소
1. 고객이 접수한 가입 신청의 내역과 상태를 본다.
2. 상태가 '접수'이면 취소할 수 있다. 취소하면 상태가 '취소'로 바뀐다.

### 4.5 예외 상황
| 상황 | 처리 |
|---|---|
| 약정이 남은 기존 고객이 요금제를 바꾸려 함 | 예상 위약금을 안내하고, 고객이 동의하면 진행한다. |
| 처리 중이거나 완료된 가입 신청을 취소하려 함 | 취소할 수 없다. 안내 문구는 확인이 필요하다. |
| 입력 정보 확인 화면에서 수정이 필요함 | 가입 신청 폼으로 돌아간다. 기준 흐름(screens.md)을 따른다. |

## 5. 비즈니스 규칙

1. **고객 구분:** 본인인증 후 U+ 가입 정보가 있으면 기존 고객, 없으면 번호이동 고객이다.
2. **추천 근거:** 기존 고객은 실제 사용량, 번호이동 고객은 직접 입력한 월 예산과 지금 내는 요금이다.
3. **추천 개수:** 요금제 3개를 보여 준다.
4. **약정 기간:** 12개월 또는 24개월 중에서 고른다.
5. **결합할인:** 받을지 여부만 고른다. 결합상품 가입은 하지 않는다.
6. **위약금:** 약정이 남은 고객에게는 예상 위약금을 안내하고 동의를 받는다.
7. **입력 정보:** 개인 정보와 결제 정보는 번호이동 고객만 입력한다.
8. **유심 유형:** 번호이동 고객만 고른다.
9. **신청 처리:** 가입 신청은 접수만 한다. 실제 변경과 개통은 나중에 처리하고 연락처로 안내한다.
10. **신청 상태:** 접수 → 처리 중 → 완료 순서로 진행한다. 접수 상태에서만 취소할 수 있고, 취소하면 '취소' 상태가 된다.
11. **금액 데이터:** 위약금과 결합할인 금액은 이번 범위에서 예시값을 쓴다. 시스템 연동은 나중에 한다.

## 6. 데이터 모델

```
고객 (Customer)
 ├─ 고객 유형: 기존 | 번호이동
 ├─ 본인인증 여부
 ├─ 개인 정보: 이름, 생년월일, 연락처, 이메일      ← 번호이동 고객만 입력
 ├─ 결제 정보: 납부 방법, 카드 명의자, 카드 번호, 유효기간  ← 번호이동 고객만 입력
 ├─ 현재 가입 정보 (기존 고객만)
 │    ├─ 현재 요금제 → 요금제
 │    ├─ 약정 종료일 / 남은 약정
 │    └─ 실제 사용량: 데이터, 통화, 문자
 └─ 추천 조건 (번호이동 고객만): 월 예산, 지금 내는 요금

요금제 (Plan)
 ├─ 이름, 월 요금
 ├─ 제공 내역: 데이터, 통화, 문자
 └─ 혜택

추천 결과 (Recommendation)
 ├─ 고객 → 고객
 ├─ 근거: 실제 사용량 | 추천 조건
 └─ 추천 요금제 3개 → 요금제

가입 신청 (Application)
 ├─ 고객 → 고객
 ├─ 요금제 → 요금제
 ├─ 신청 유형: 요금제 변경 | 번호이동 가입
 ├─ 약정 기간: 12개월 | 24개월
 ├─ 결합할인 여부: 예 | 아니오
 ├─ 결합할인 금액 (예시값)
 ├─ 유심 유형: 일반 유심 | eSIM   ← 번호이동 가입만
 ├─ 예상 위약금 (예시값) + 위약금 동의 여부   ← 약정이 남은 기존 고객만
 ├─ 상태: 접수 | 처리 중 | 완료 | 취소
 └─ 접수 일시
```

- 고객 1명은 가입 신청을 여러 건 가질 수 있다. 이 관계는 가정이므로 확인이 필요하다.
- 화면에 표시하는 요금제, 금액, 신청자 정보는 예시값이다.

## 7. 이번 범위에서 하지 않을 것

- 휴대폰(단말) 구매, 보조금 신청
- 부가서비스(OTT 등 구독 상품)
- 결합상품(인터넷, TV, 가족결합) 가입
- 상담사와 운영자용 화면
- 위약금과 결합할인의 실제 금액 계산과 시스템 연동

## 8. 열린 질문

1. 처리 중이거나 완료된 가입 신청을 취소하려 할 때 어떤 안내를 보여 주나요?
2. 고객 1명이 동시에 가입 신청을 여러 건 접수할 수 있나요?
3. 기존 고객이 추천 결과를 받으려면 실제 사용량을 몇 개월치 기준으로 보나요?
4. 번호이동 고객의 월 예산은 금액을 직접 입력하나요, 아니면 구간 중에서 고르나요?
5. 가입 신청 결과는 어떤 연락처, 어떤 수단(문자, 알림 등)으로 안내하나요?
6. 1장 배경의 추정 내용이 실제와 맞나요? (약정 만료 통보, U+one 앱 확인, 고객센터 전화, 보조금 때문에 비싼 요금제에 가입하는 비율)
7. 로그인과 본인인증 중 어느 것을 쓰나요, 아니면 둘 다 지원하나요?
8. 이 서비스와 U+one 앱은 어떤 관계인가요? (별도 모바일 웹인지, 앱에서 연결되는지)
