# PRD — 요금제 추천·구독 서비스 (모바일 웹)

> 근거 문서: [DOMAIN.md](DOMAIN.md) (용어, 규칙, 데이터 모델), [screens.md.txt](screens.md.txt) (기준 화면 흐름)
> 용어는 DOMAIN.md를 따른다. 화면과 문서에서는 '가입'으로 통일한다.
> "확인 필요"는 아직 정해지지 않은 내용이다. 구현할 때 임의로 정하지 않는다.

## 1. 개요

### 1.1 문제
- 고객은 약정이 끝나면 더 싸게 쓰려고 요금제를 바꾸려 한다.
- 하지만 요금제가 너무 많고, 혜택과 결합할인, 약정 기간을 이해하기 어려워서 결정하지 못한다.
- 결국 고객센터에 전화하는 경우가 많다. (추정)

### 1.2 목표
- 고객이 고객센터에 전화하지 않고 모바일 웹에서 요금제를 비교하고 가입 신청까지 끝낸다.
- 고객에게 맞는 요금제를 3개로 좁혀서 보여 준다.
- 혜택, 결합할인, 약정 기간, 위약금을 가입 전에 이해할 수 있게 보여 준다.

### 1.3 성공 지표
- 확인 필요. 인터뷰에서 다루지 않았다.

## 2. 사용자

| 사용자 | 구분 기준 | 목표 |
|---|---|---|
| 기존 고객 | 본인인증 후 U+ 가입 정보 있음 | 실제 사용량에 맞는 더 저렴한 요금제로 바꾼다. |
| 번호이동 고객 | 본인인증 후 U+ 가입 정보 없음 | 월 예산과 지금 내는 요금을 기준으로 U+ 요금제에 가입한다. |

## 3. 유저 스토리

1. **US1.** 기존 고객은 더 싸게 쓰기 위해 실제 사용량을 바탕으로 추천받은 요금제 3개를 비교한다.
2. **US2.** 번호이동 고객은 자기에게 맞는 요금제를 찾기 위해 월 예산과 지금 내는 요금을 입력하고 추천 요금제 3개를 본다.
3. **US3.** 고객은 요금제를 결정하기 위해 혜택, 결합할인, 약정 조건을 가입 전에 확인한다.
4. **US4.** 약정이 남은 기존 고객은 손해를 미리 알기 위해 예상 위약금을 확인하고 동의한 뒤 진행한다.
5. **US5.** 고객은 고객센터에 전화하지 않고 끝내기 위해 모바일 웹에서 바로 가입 신청을 한다.
6. **US6.** 고객은 마음이 바뀌었을 때를 대비해 가입 신청 내역을 보고, 접수 상태이면 취소한다.

## 4. 범위

### 4.1 포함
- 로그인 또는 본인인증과 고객 유형 구분
- 추천 조건 입력 (번호이동 고객)
- 요금제 추천 3개, 요금제 상세
- 가입 신청: 기존 고객 흐름과 번호이동 고객 흐름
- 위약금 안내와 동의 (약정이 남은 기존 고객)
- 가입 신청 완료, 가입 신청 내역 조회와 취소

### 4.2 제외
- 휴대폰(단말) 구매, 보조금 신청
- 부가서비스(OTT 등 구독 상품)
- 결합상품(인터넷, TV, 가족결합) 가입. 결합할인 여부 선택만 한다.
- 상담사와 운영자용 화면
- 위약금과 결합할인의 실제 계산과 시스템 연동. 이번에는 예시값을 쓴다.

### 5.1 흐름
- **기존 고객:** S1 → S3 → S4 → S6 → S8 → S9
- **번호이동 고객:** S1 → S2 → S3 → S4 → S5 → S6 → S7 → S8 → S9
- **내역:** S10에서 가입 신청을 조회하고 취소한다. S10으로 들어오는 경로는 확인 필요.

### 5.2 화면별 요구사항

**S1 로그인 · 본인인증**
- 로그인하거나 본인인증을 하면 U+ 가입 정보를 조회한다.
- 가입 정보가 있으면 기존 고객으로 S3, 없으면 번호이동 고객으로 S2로 간다.
- 로그인과 본인인증 중 무엇을 지원할지는 확인 필요.

**S2 추천 조건 입력 (번호이동)**
- 월 예산과 지금 내는 요금을 입력한다.
- 입력 방식(직접 입력 또는 구간 선택)은 확인 필요.

**S3 요금제 추천**
- 추천 요금제 3개를 `Card/Plan`으로 보여 준다.
- 기존 고객은 실제 사용량, 번호이동 고객은 S2의 입력값을 근거로 추천한다.
- 카드를 누르면 S4로 간다.

**S4 요금제 상세**
- 월 요금, 제공 내역(데이터, 통화, 문자), 혜택을 `List/Row`로 보여 준다.
- 결합할인을 받으면 얼마가 되는지, 약정 조건(12개월, 24개월)을 안내한다. 금액은 예시값이다.
- `BottomCTA` "가입하기" → 기존 고객은 S6, 번호이동 고객은 S5.

**S5 가입 폼 · 개인 정보 (번호이동)**
- screens.md 03과 같다. 이름, 생년월일, 연락처, 이메일을 입력한다.

**S6 가입 폼 · 요금제 옵션**
- `FilterChip`으로 약정 기간(12개월, 24개월)과 결합할인 여부(예, 아니오)를 고른다.
- 번호이동 고객은 유심 유형(일반 유심, eSIM)도 고른다.
- 약정이 남은 기존 고객에게는 예상 위약금(예시값)을 보여 주고 동의를 받는다. 동의하지 않으면 다음으로 갈 수 없다.
- 위약금 안내를 이 화면에 둘지, 별도 화면으로 둘지는 확인 필요.

**S7 가입 폼 · 결제 정보 (번호이동)**
- screens.md 05와 같다. 납부 방법, 카드 명의자, 카드 번호, 유효기간을 입력한다.

**S8 입력 정보 확인**
- 고객 유형에 맞는 항목만 보여 준다.
  - 기존 고객: 요금제와 옵션, 위약금 동의 여부
  - 번호이동 고객: 개인 정보, 요금제와 옵션, 결제 정보
- `BottomCTA` double: "수정" → 가입 폼 첫 단계, "가입 신청" → S9.

**S9 가입 신청 완료**
- 가입 신청이 '접수'되었음을 알리고 신청 요약을 보여 준다.
- 실제 변경과 개통은 나중에 처리되고 연락처로 안내된다고 알린다.

**S10 가입 신청 내역**
- 가입 신청 목록과 상태(접수, 처리 중, 완료, 취소)를 보여 준다.
- 상태가 '접수'인 신청만 취소할 수 있다. 취소하면 '취소'로 바뀐다.
- 처리 중이거나 완료된 신청에 보여 줄 안내 문구는 확인 필요.

## 6. 비즈니스 규칙

DOMAIN.md 5장을 따른다. 구현할 때 꼭 지켜야 할 규칙은 다음과 같다.
1. 추천 요금제는 3개다.
2. 약정 기간은 12개월 또는 24개월이다. 무약정은 없다.
3. 개인 정보, 결제 정보, 유심 유형은 번호이동 고객만 입력한다.
4. 약정이 남은 기존 고객은 위약금에 동의해야 진행할 수 있다.
5. 가입 신청은 접수만 하고, 접수 상태에서만 취소할 수 있다.

## 7. 데이터

DOMAIN.md 6장의 데이터 모델을 따른다. 고객, 요금제, 추천 결과, 가입 신청 네 가지다.
- 화면에 표시하는 요금제, 금액, 신청자 정보는 예시값이다.

- 본인인증 실패, 추천 결과가 없는 경우의 처리도 확인 필요.
